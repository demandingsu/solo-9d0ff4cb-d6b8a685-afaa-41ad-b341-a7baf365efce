# 古籍制版 · 字模工位管理

几册古籍陆续送到同一制版工位、共用外字字模。本服务管理分册用字与优先字库清单，
在每次“交印”时算出工位上字模的**增减单**：哪些字模要补备、哪些可以撤下。
交印单与当次实际用模的**逐页记录**一同入档；发现字模缺损时，可按
**字库＋版次＋字模号** 回查哪些交印单、哪一册、哪几页需要重做。

## 业务规则

1. 上传**按优先顺序排列的字库清单**（CSV：`字库,版次,字模号,字`），文件顺序即优先级。
2. 上传**分册用字表**（CSV：`字`，每格可多字、可无表头；**或 `页码,字` 两列**，逐页记录用字，
   字格可连写多字、同字可跨页），从中提取分册用字清单。
3. 每个字取**第一个收录它的字库**中的字模，按 **(字库, 版次, 字模号)** 识别字模。
4. 交印一册时**只更新该册**选用的字模；其余册沿用各自上次交印的清单（从未交印的册不参与共需）。
5. 比对交印前后**各册共需字模的并集**，生成增减单；只有最后一个使用某字模的册撤下它时，才出现“减”项。
6. **并发交印按生效次序逐单出单**：进程内互斥锁 + SQLite `BEGIN IMMEDIATE`/WAL/忙等待双重保证，
   每单提交前后都校验并集与各册 active 清单一致，不一致即回滚报错。
7. **逐页用模随单入档**：交印单快照内含当次实际用模的逐页记录（无页码表则为空），
   同时按 (字库, 版次, 字模号) 写入索引表 `order_matrix_pages`；改稿或换库后历史单仍在档，
   回查走索引、无需逐单扫描；匹配到的无页码单一并列出，标为**页码未知**。
8. **重复确认复用原单**：
   - 带 `Idempotency-Key` 请求头：同键永远返回同一单；
   - 不带键：同册、同用字、**同页码分布**、解析目标与当前已交印清单完全相同（稿件与用模都未变）时，
     复用该册最近一单；**用字所在页有变化即使用模相同也出新单**，补上页码或改回无页码表同样算变化，
     改回后的新单回查时标页码未知；
   - 按单号 `GET /api/orders/{单号}` 可原样重取，`.../download` 下载 CSV（含逐页记录）。
9. **缺字或保存失败时整笔回滚**，各册仍沿用原清单，共需并集与回查结果都保持原状，不产生新单。

## 目录

```
app/            FastAPI 应用（database/parsers/service/main）
web/index.html  单页操作界面（上传、交印、重取、字模回查、状态总览）
samples/        网页与接口可直接使用的样例 CSV（1 份字库清单 + 2 册用字表 + 1 份带页码用字表）
tests/          pytest 端到端测试（20 个用例）
Dockerfile / docker-compose.yml
```

## Docker Compose 启动

```bash
docker compose up --build
# 打开 http://localhost:8000/
# SQLite 数据持久化在命名卷 matrix-data -> /data/matrix.db
```

页面上可直接下载 `/samples/` 下的样例文件，按 ① 字库清单 → ② 用字表 → ③ 交印 的顺序操作。

## 本地运行（无 Docker 时）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 测试
pip install -r requirements-dev.txt
pytest -q
```

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/libraries` |  multipart 上传字库清单 CSV，全量替换当前生效清单 |
| POST | `/api/volumes/{册名}/chars` | 上传该册用字表 CSV（`字` 或 `页码,字`），全量替换用字 |
| POST | `/api/volumes/{册名}/submit` | 交印并出增减单；可选 `Idempotency-Key` |
| GET  | `/api/orders?volume=册名` | 按生效次序列出单据 |
| GET  | `/api/orders/{单号}` | 按单号原样重取 JSON（含逐页记录） |
| GET  | `/api/orders/{单号}/download` | 下载增减单 CSV（带 BOM，Excel 直开，含逐页记录） |
| GET  | `/api/lookup?library=&edition=&matrix_no=` | 按 字库＋版次＋字模号 回查：单号、册名、页码（无页码单标页码未知） |
| GET  | `/api/state` | 当前字库、各册用字（含页码）/已交印字模、共需并集 |
| POST | `/api/reset` | 清空全部数据（演示用） |
| GET  | `/docs` | Swagger 交互文档 |

增减单 JSON 关键字段：`added` / `removed`（共需池层面的增减，含字库/版次/字模号/字）、
`pool_before` / `pool_after`（交印前后共需并集）、`volume_before` / `volume_after`（该册清单）、
`has_pages` / `pages`（当次实际用模的逐页记录，无页码表则为 `null`）。
回查返回 `matches`：`order_no` / `volume` / `pages`（`pages_unknown=true` 时 `pages` 为 `null`）。

## 数据模型（SQLite）

- `libraries`（字库+版次，优先级，current 标记）、`glyphs`（字库内字模号→字）
- `volumes` / `volume_chars`（册与用字，保留用字顺序）、`volume_char_pages`（用字所在页，可空）
- `active_matrices`（各册**上次交印**生效的字模清单）
- `submit_seq`（全局生效序号）、`orders`（单号、幂等键、指纹、整单 JSON 快照含逐页记录）
- `order_matrix_pages`（随单归档的用模记录：字模身份文本快照 + 页码，
  `(字库, 版次, 字模号)` 上建索引；页码 NULL 表示无页码单。旧库升级时自动按单快照回填）

## 做完了什么 / 验过什么 / 未完成

### 已完成

- FastAPI + SQLite 全量功能：字库/用字上传、优先选库、交印出单、单据重取与 CSV 下载、状态总览、单页网页与样例数据。
- **带页码用字表**：`页码,字` 两列 CSV（字格连写多字、同字跨页、重复行去重），从中提取分册用字清单；
  无页码旧格式照常可用。
- **逐页用模随单入档**：交印单 JSON 快照含 `pages` 逐页记录，同步写入 `order_matrix_pages` 索引表；
  单据 CSV 下载附逐页记录；旧库升级自动回填（无页码旧单标页码未知）。
- **字模回查**：`GET /api/lookup` 按 字库＋版次＋字模号 走索引回查，列出单号、册名、页码；
  无页码单一并列出标页码未知；网页新增“⑤ 字模回查”卡片，状态面板点字模即填即查。
- **判重升级**：无键确认时指纹纳入页码分布——换页、补页码、改回无页码表都出新单；
  稿件与用模都未变才复用原单；幂等键重试仍取原单。
- 并发串行化（应用锁 + 数据库立即事务 + WAL + 30s 忙等待）、缺字/保存失败整笔回滚
  （共需并集与回查结果都保持原状）。
- Dockerfile 与 docker-compose（命名卷持久化、健康检查），沿用 `docker compose up --build` 启动。

### 已验证（本环境实际运行）

- `pytest` 20 个用例全部通过，含题目指定的**两册先后弃用同一字模**与新增页码场景：
  换页出新单（增减为空、用模相同）、补页码/改回无页码都算变化且改回后标页码未知、
  无变化复用、幂等键重试、失败回滚后共需与回查原状、换库后历史页码仍可查、
  回查 SQL 命中 `idx_omp_matrix` 索引（EXPLAIN QUERY PLAN 验证，无需逐单扫描）。
- 真实启动 uvicorn 用样例 CSV 冒烟：上传带页码册甲（14 字 7 页）→ 交印单含逐页记录 →
  回查“天”得册甲页一 → 册乙无页码交印后共享字模“玄”回查同时列出带页单与页码未知单 →
  换页（天 页一→页九）出新单且新旧页码并存在档 → 无变化重试复用 → 幂等键重试同单 →
  模拟保存失败（HTTP 500）后共需池与回查命中数不变 → 换库后旧字模历史页码仍可查 →
  首页与 CSV 下载（含逐页记录）正常。
- 旧版 `data/smoke.db` 副本升级：自动建表并回填 4 单 12 行用模记录，回查标页码未知，
  重复初始化幂等；升级后无变化重交仍复用旧单（无页码指纹格式向后兼容）。
- 4 册多线程并发交印：单号连续、逐单共需与当时各册并集一致（既有用例保持通过）。
- 编码回退（UTF-8 BOM / GB18030）、无表头用字表、坏表头 400、页码为空 400、
  有页码缺字列 400、未知册/单号 404、回查参数不全 400。

### 未完成 / 限制

- 本环境没有 Docker 守护进程，`docker compose up --build` 仅做了文件级准备，未实机构建运行；
  Dockerfile 基于 `python:3.11-slim` 与已验证的依赖版本，逻辑上与本地运行一致。
- 应用级互斥锁只在单进程内生效；多进程/多副本部署时依赖 SQLite 的立即事务与忙等待兜底，
  建议仍以单副本 + 卷持久化方式运行（compose 默认即如此）。
- 字库清单替换为管理操作：替换后已交印册仍锁定在旧字模（保留历史可追溯），
  重新交印时才按新清单解析；未对替换操作加单独权限控制。
- 回查按精确三元组（字库, 版次, 字模号）匹配，不支持模糊/批量查询；页码按原文本存储与展示，
  未做页码排序规范化（如“一/1”混排时按出现顺序列出）。
- 没有账号/鉴权与操作审计（题目未要求）；`/api/reset` 仅适用于演示环境。
